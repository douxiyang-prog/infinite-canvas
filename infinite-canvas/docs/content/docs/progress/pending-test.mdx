# Pending Tests

The current release needs manual verification in these areas:

- Agent backends: after starting the updated Canvas Agent, the Agent panel should show a runtime switch for `Ark native API`, `DeepSeek Harness`, and `Canvas channel`. With a valid Volcengine Ark Agent Plan API key, native mode should stream a response directly from the Ark Messages API, while Harness mode should use the isolated `~/.infinite-canvas/dsh` profile. In Canvas channel mode, a current user's text channel with a Base URL, `sk-...` API key, and text model should stream through its OpenAI-compatible Chat Completions endpoint without saving the channel key in Agent config or logs; relative Base URLs such as `/provider` should be resolved against the Canvas site origin before being sent to the local Agent, host-only Base URLs should default to `https://`, local hosts to `http://`, and malformed URLs should return a clear configuration error instead of a server error. Switching back to Ark or Harness should refresh the model list. All modes should preserve chat history, model selection where supported, image input where supported, and stop controls. Setting `CANVAS_AGENT_RUNTIME=codex` must restore the previous Codex behavior.
- Agent turn completion: a Canvas channel reply must clear the elapsed “thinking” indicator and re-enable the input as soon as its `turn.completed` event arrives, even if history persistence or a later idle-state event is delayed.
- Canvas channel reconnect: after restarting the local Canvas Agent with the browser still open, the page should reconnect and automatically send the previously selected Canvas channel, resolved Base URL, key, and model to the new Agent process. The next message should not fail with “select a Canvas channel”.
- Canvas Agent Manager: the Windows installer should start without a separate Node.js installation, show the local URL and token, start/stop/restart the Agent, preserve settings, minimize to the tray, and restore the selected runtime. Closing Agent through the manager must use the token-protected shutdown endpoint and leave no orphan process. Running a newer `setup.exe` directly must overwrite the existing per-user installation without version comparison. Installing on one computer must not imply that other computers can connect to that loopback Agent.
- Public tunnel loading: with gzip enabled, the main JavaScript asset served through the public tunnel should return `Content-Encoding: gzip` and load substantially faster than the previous 3.9 MB response. The HTML should show `正在加载无限画布…` until React replaces it.
- Project scenes: existing canvases remain ungrouped at the top of each project. Administrators manage scene groups in Global Settings. Every project member can see all scene dividers, expand or collapse each scene locally, and use Import canvases or New canvas on the divider. Scenes start collapsed so multiple scene headers fit on one page; collapsing is layout-only and never hides or restricts access. Administrators can rename and delete scenes, while normal members cannot. Deleting a scene preserves its canvases by moving them back to the ungrouped area.
- Project pages: `/projects` should show only project cards with member, canvas, and scene summaries. Selecting a card opens `/projects/:projectId`, where only that project's ungrouped canvases, scene dividers, project assets, import, and new-canvas actions are visible. The assets page should return to that project detail page, and a missing or inaccessible project should show a safe not-found view.
- Project SQL regression: `/api/projects` and direct project access must return valid JSON rather than a server error after the scene migration, and saving a canvas must not report an internal server error when the scene column exists.
- Unified admin navigation: Global Settings should expose all configuration, project scene, branding, user management, and per-user channel assignment tabs in one horizontally scrollable menu. `/admin/users` and `/admin/user-channels` must redirect to the matching settings tab, user-channel links must retain the selected user, and the account menu should no longer duplicate those admin destinations.
- Canvas generation cost: the image prompt panel should show the current model channel's estimated total before the generate button, using that channel's public pricing and selected image count. For `doubao-seedream-5.0-pro-260628`, one image at `$0.082` and CNY exchange rate 7.3 should show `¥0.60`, while three images should show `¥1.80`. Unknown or non-image pricing must display an unavailable estimate rather than a fabricated amount.
- New API channel balances: the account area should show remaining / total quota for the current model channel using that channel's own Base URL and API Key. Opening the badge should list every channel visible to the current user with its independently queried balance, without querying unassigned channels. The badge should display `∞` for the unlimited sentinel and refresh when requested, after 30 seconds, or when the window regains focus.
- New API internet monitoring: when channels use the public Canvas domain followed by `/provider`, nginx should proxy `/provider/api/status`, `/provider/api/pricing`, and `/provider/v1/dashboard/billing/*` to the LAN New API without exposing its admin UI. Balance and image pricing must work through that same-origin path for remote users.
- Windows source archive deployment: building the frontend from an archive created on Windows must produce an nginx container that remains running, because `web/docker-entrypoint.sh` must be normalized to LF before execution.
- Invalid reference images must fail locally before an API request with a readable image-read error. A valid reference image should decode to a non-empty byte array and must never reach the provider as an empty file or relative `/api/files/...` path.
- Custom model scripts: provider 4xx responses should surface the HTTP status and nested `error.message`/`message`/`msg` response detail in the UI instead of only “Request failed with status code 400”.
- Reference-key compatibility: image-to-image must accept raw `image:...` storage keys, `/api/files/...` URLs, Blob URLs, and existing `data:image/...` values. Every form should reach a model script as a valid Base64 Data URL.
- Image references after server migration: switching image models or running edits, angle changes, masks, upscales, and video generation with references must convert `/api/files/...` sources and storage keys into valid `data:image/...;base64,...` values before calling the provider. The provider must not receive a relative URL in a Base64 image field.
